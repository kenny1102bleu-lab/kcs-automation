# Rationale: 朝礼を「各スタッフへの方向性トリガー」として再設計

- **日付:** 2026-07-08
- **対象ファイル:** `GAS_KCS合同会社_Backend.js` の `morningBriefing()` 内 `briefContext`（Geminiプロンプト）
- **社長指示（要約）:**「朝礼は各スタッフへの方向性のトリガーになってほしい。昨日の実績・レポート・本日のニュースから最強の状態に持っていける指示を探し当てて実行してほしい。毎日AI関連ニュースでは実効性が無い。専務がしきって結論を出してほしい」

## 1. 問題点（変更前）

1. **WEB検索指示が無条件のAI業界トレンド探索になっていた**（「AI技術、ガジェット、アパレル、バーチャルインフルエンサー」等をキーワード列挙）。結果、毎朝「AIエージェント」「AIインフルエンサー市場」のような一般論が差し込まれ、KCSの実務判断に紐づかない filler になっていた（2026-07-08朝の実例で発覚）。
2. **司会・結論役がサクラ秘書**で、ジュン専務は議論の一発言者に過ぎず、「専務が仕切って結論を出す」構造になっていなかった。
3. **`[PROJECT:xxx]`タグの中身が空プレースホルダのまま出力されうる**設計（`...（本日の具体的な指示や確認事項）`をGeminiがそのまま埋めずに残す/曖昧に書く余地があった）。

## 2. 変更内容

### WEB検索指示
- AI業界全般の一般トレンド解説（AIエージェント／AIインフルエンサー等）の検索・紹介を明示的に禁止。
- 検索してよいのは「(1) 現状データ（実績・課題）と具体的に紐づく」「(2) 検索結果がそのままHAL担当／すなくん担当への具体的指示に変換できる」の両方を満たす場合のみ。
- 材料が無ければニュースを無理に差し込まず「実績データのみで判断」してよいことを明記。

### 役割と権限の再定義
- **ジュン専務＝最終決定権者。** 議論を評価し、本日の結論（担当ごとの指示）を確定して言い渡す役に変更。
- サクラ秘書は現状データの読み上げ＋ジュン専務の結論の書記・整理役に縮小（司会・結論役から外した）。
- ハルキが実績分析→実行案のたたき台作成、アカリが（条件を満たす場合のみ）裏付け情報提供、という順に再配置。

### ディスカッションの流れ
サクラ（データ読み上げ）→ ハルキ（実績分析）→ アカリ（裏付け・任意）→ ジュン専務（評価・結論）→ サクラ（結論の箇条書き整理）に変更。旧フローは「サクラ司会→アカリのトレンド発表→ジュン専務→ハルキ→サクラまとめ」で、結論の発信者が曖昧だった。

### 出力ルール
`[PROJECT:xxx]`タグにプレースホルダのまま出力することを明示的に禁止。「なぜ（根拠データ）」＋「何を・いつまでに（具体的指示）」のセットを必須化。特筆事項が無い場合は「通常運用を継続」と明記させることで、空欄や曖昧記述を防止。

## 3. 期待効果 / リスク

| 変更 | 期待効果 | リスク |
|---|---|---|
| AI業界ニュースの無条件検索を禁止 | 毎日同じ話の水増しが無くなり、実績データに基づく判断に集中する | 検索条件を満たすニュースが無い日が続くと[MAIN]がやや短くなる可能性→許容範囲として明記済み |
| ジュン専務を結論役に固定 | 「専務が仕切って結論を出す」という社長要望どおりの構造になる | Geminiが指示に従わずサクラ主導の出力を続ける可能性→数日分の出力を見て要調整 |
| PROJECTタグのプレースホルダ禁止 | 各担当への指示が具体化される | データが薄い日は「通常運用を継続」に倒れやすく、指示が単調になる可能性→実績データ（snsStats等）の粒度向上が今後の課題 |

## 4. 今後の確認事項

- 数日分の朝礼出力を見て、ジュン専務が実際に結論役として機能しているか、AI業界ニュースの再発が無いかを確認する。
- 「昨日の実績」データ（`getYesterdaySnsStats()`）が投稿数・いいね・インプレッションのみで薄いため、より詳細な内訳（投稿別パフォーマンス等）を渡せると指示の質がさらに上がる可能性がある。
